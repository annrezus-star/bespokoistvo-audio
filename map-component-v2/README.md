# Москва психологическая — исправление управления и подложки

Отдельный компонент MapLibre GL JS 5.6.1 + OpenFreeMap. Другие страницы, поставщик карты и исходные координаты не изменены. Исходная версия сохранена коммитом `07f9d3d80d5f02e91776284bce2f97868ffb05a8` и веткой `bespokoistvo-map-v2`; изменения — в `bespokoistvo-map-fixes`.

**Задача не завершена полностью: достоверная пешая геометрия пока не получена.** Причина — активный сетевой allowlist среды, а не отсутствие API-ключа. Ни тестовая, ни декоративная линия в демонстрацию не добавлена.

## Демонстрация и запуск

https://raw.githack.com/annrezus-star/bespokoistvo-audio/bespokoistvo-map-fixes/map-component-v2/map-demo.html

Локально из папки компонента: `python3 -m http.server 8083`, затем `http://localhost:8083/map-demo.html`. Необходим доступ к `tiles.openfreemap.org`. Скрипты SDK находятся в `vendor/`; сборка и ключ не нужны.

## Исправленные причины

1. **Wheel:** `cooperativeGestures:true` требовал Ctrl/⌘. В самостоятельной демонстрации теперь явно `cooperativeGestures:false` и `scrollZoom:true`. Сообщение об ошибке больше не перехватывает wheel/drag (кнопка повтора остаётся кликабельной). Событие wheel выводит карту из режима автоматического обзора, чтобы последующее изменение размера служебных элементов не сбрасывало положение. Повторный `create` в том же контейнере удаляет прежний экземпляр вместо наложения двух карт.
2. **Белая сетка:** `road_area_pattern` использовал спрайт `pedestrian_polygon`. Убрана именно текстура; пешеходные площади остаются спокойной заливкой. Дорожки `road_path_pedestrian`, `tunnel_path_pedestrian`, `bridge_path_pedestrian` стали тонкими сплошными и появляются при приближении. Железнодорожная штриховка отключена; административные пунктиры не выводятся на городском масштабе.
3. **Метро:** предыдущий фильтр включал `subway_entrance`, поэтому подписывался каждый вход. Входы исключены, оставлены именованные станции. Вместо повторяющегося крупного «М» — небольшая подпись «м. название», с дополнительным пространством для коллизий.
4. **Большие зелёные территории:** `park` в OpenMapTiles содержит также охраняемые и исторические территории — это не достоверное покрытие растительностью. Его сплошная заливка и контур отключены. Зелень осталась у фактических `landcover_wood` и `landcover_grass`; у песка, льда и спортивных площадок убраны ошибочные зелёные заливки. Источник схемы: https://github.com/openmaptiles/openmaptiles/blob/master/layers/park/park.yaml .

На широком контейнере от 760 px добавлены названия остановок через механизм коллизий MapLibre. Прозрачная область 48×48 в движке резервирует место для номерного маркера; подписи могут скрываться, когда не помещаются рядом с другими подписями. На телефоне остаётся карточка выбранного места.

Маркеры 01–08 имеют область 44×44 px, выбранный кружок крупнее. Экранные выноски 05/06 сохраняют истинные позиции объектов; 06 юго-восточнее 05. Никаких новых архитектурных рисунков нет.

## Маршрут: что сделано и что блокирует результат

В проекте найдены только файлы с непроверенным статусом и `coordinates:null`. Подходящей GeoJSON/GPX/KML-геометрии нет. Запрос настоящего пешего backend FOSSGIS `https://routing.openstreetmap.de/routed-foot/route/v1/foot/…` со всеми восемью точками блокируется до ответа маршрутизатора: **CONNECT 403 Forbidden**. В активной сетевой политике разрешён preset `package_managers`, а домена маршрутизатора нет. Автомобильный профиль не использовался.

Сохранён сетевой черновик с дополнительными доменами:

- `routing.openstreetmap.de` — один расчёт пешеходного пути;
- `overpass-api.de` — проверка путей, переходов и access-тегов;
- `tiles.openfreemap.org` — живая подложка, шрифты и значки;
- `raw.githack.com` — проверка опубликованной демонстрации.

Черновик сам не меняет работающую сеть. Минимальное действие для продолжения: **проверить и сохранить изменения в настройках среды, затем опубликовать среду**. После применения нужно заново получить пешую линию и проверить семь участков, особенно выход к общедоступной улице у Психологического института. Альтернатива — предоставленная владельцем проверенная пешая GeoJSON/GPX-геометрия. Проход во двор 07 не гарантируется.

В `route-status.json` записаны источник, причина блокировки и семь непроверенных участков. `geometryFile:null`; `route.geojson` намеренно не создан.

`route.js` уже загружает **только сохранённые локальные файлы**. Посетитель не делает запросов к маршрутизатору. После получения и проверки настоящего пути:

1. Записать `route.geojson` как FeatureCollection из семи LineString в порядке 01→02, …, 07→08. Для каждого участка указать `properties.from`/`to` со стабильными id из `stops.js`, `verification:'checked'`, `publicAccess:true` только после проверки доступности.
2. Сохранить источник/дату/пешеходный профиль в `route-status.json`; поставить `status:'ready'`, `geometryFile:'route.geojson'`. Не выставлять эти статусы автоматически только по HTTP 200 маршрутизатора.
3. Доступные подходы хранить отдельно в `approachCoordinates` с пояснением источника, не менять `coordinates` объектов. Если путь заканчивается на улице, линия не должна искусственно продолжаться к зданию через двор.
4. Перепроверить геометрию семи участков, совместимость концов и доступные переходы. Входы по-прежнему не считаются подтверждёнными только на основании координат объекта.

Загрузчик отвергает автомобильный профиль, неполные/переставленные участки и отсутствие подтверждения публичного подхода. Только после этого линия рисуется сплошным розовым 4.5 px с тонкой оливковой обводкой, над подложкой и под номерами. Обзор учитывает также геометрию пути. Сейчас эта ветка отображения не означает наличия готовой линии.

## Встраивание в Тильду

Простой вариант — T123 с iframe; высоту задаёт родительская страница:

```html
<iframe src="https://raw.githack.com/annrezus-star/bespokoistvo-audio/bespokoistvo-map-fixes/map-component-v2/map-demo.html"
  title="Москва психологическая — карта прогулки"
  style="display:block;width:100%;height:560px;border:0" loading="lazy"></iframe>
```

Для постоянного проекта лучше разместить папку на своём HTTPS-хостинге. Сам компонент работает в контейнере любой заданной высоты, от ширины 320 px; рекомендуемая минимальная высота 360 px. Только демонстрационный HTML использует высоту экрана.

Для прямой интеграции подключите `vendor/maplibre-gl.js`, `stops.js`, **`route.js`**, затем `map.js`:

```js
const widget = BespokoistvoMap.create(document.getElementById('your-map'), {
  stops: BespokoistvoStops,
  cooperativeGestures: true, // Встраивание в длинную страницу: отдельная настройка.
  onStopSelect(id) { /* Обновить внешний аудиогид. Карта не запускает звук. */ }
});
widget.ready.catch(() => {});
widget.selectStop('mosselprom');
widget.fitRoute();
widget.destroy();
```

`selectStop(id,{notify:false})` подавляет обратное событие; `fitRoute()` закрывает карточку и возвращает обзор, `{keepCard:true}` учитывает открытую карточку; `destroy()` очищает SDK, наблюдатели, таймеры и запрос загрузки маршрута. Событие `bespokoistvo:stopselect` содержит `{id,order,coordinates}`. `getStatus()` отдельно сообщает состояние подложки и маршрута. `ready` подтверждает реальные отрисованные векторные улицы/здания, а не весь проект с маршрутом.

CSS изолирован Shadow DOM. При прямой загрузке с другого домена нужны CORS для JSON/CSS и CSP с разрешением ресурсов хостинга, `connect-src https://tiles.openfreemap.org`, `worker-src blob:`. В iframe события и API находятся внутри фрейма; для связи с родителем потребуется отдельный адаптер с проверкой origin. Автозвука и геолокации нет.

## Проверка и ограничения

После исправлений в Chromium проверены **реальное колесо без клавиш-модификаторов**, drag, +/−/«Весь маршрут», **реальный двухпальцевый жест**, восемь маркеров, обновление карточек, ширина 320 px без горизонтального переполнения, однократная инициализация, destroy и отсутствие локальных ошибок JS/HTML/CSS/JSON. Для маркеров при заблокированной подложке обработчики проверены DOM-событиями: это не заявляется проверкой клика по видимой живой карте. Спецификация JSON-стиля прошла валидацию. Искусственная диагностическая геометрия использовалась только для теста отбраковки профиля driving/непроверенных подходов; она не сохранена и не опубликована как маршрут.

**Не прошли:** живая загрузка тайлов, спрайтов и шрифтов OpenFreeMap из среды; получение маршрута; проверка семи пеших участков. Причина — сетевой allowlist. Наличие этих ошибок не засчитывается как готовность карты. Визуальное поведение новых подписей на живой подложке и опубликованная Тильда не проверены. Скриншоты не создавались.
